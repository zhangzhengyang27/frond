## 二、视觉层（按优先级）

### V1 [P0] 搜索行结构对齐
- 基准：64pt 行高 = 16pt 上 padding + 32pt 输入框 + 16pt 下 padding；左侧 22pt 应用图标 + 12pt 间距后接输入框（x=50pt）；placeholder「Search for apps and commands…」。
- 现状：`--launcher-search-height: 54px`，输入框 53px 几乎占满整行、顶到窗沿；图标 18px。
- 建议：token 改 64px，输入框高 32px 垂直居中，图标 22px，标题/输入 x 基线对齐 50px。这是逐屏可见的最大结构差。

### V2 [P0] 列表行密度对齐
- 基准：38pt 行距、图标 22×22、右侧单个类型标签（Command / Application / AI Extension）+ 数字徽标 1-0。
- 现状：44px 行距、图标 ~17px、右侧**两个**标签（「动作 / 剪贴板 / 应用 / 文件」+「Command」）+ 徽标。
- 建议：行距 38px、图标 22px；去掉逐行固定的「Command」字样（Raycast 该位置放的是模块来源标签，且多数根列表行只显示类型）；标签数 ≤1。

### V3 [P0] 徽标 0 重复 bug
- 现状：查询态第 10 行之后所有行徽标都显示「0」（s-19 观测到 4 个「0」并存）。
- 基准：Raycast 只给前 10 项发 1-0，之后的行**无徽标**。
- 建议：徽标只渲染 rank ≤ 10 的行。

### V4 [P0] 底部操作栏布局对齐
- 基准：`[28pt 图标按钮] ……… [主操作按钮 ↵] [Actions ⌘K]` 全部右对齐、按钮 28pt 高；主操作文案随选中项变化（见 I2）。
- 现状：`[↵ 执行 77×33] …… [⌘K 动作 83×33] [28×28 图标按钮]`——主操作在**左**、⌘K 居右、按钮 33px。
- 建议：按钮高 28px；布局改为左图标按钮 + 右侧「主操作 ↵」「Actions ⌘K」。

### V5 [P1] 分区头样式
- 基准：Title Case（"Suggestions" / "Results" / "Files" / "Calculator"），14pt 高（≈11-12px 字号）灰字，左边距 16pt。
- 现状：全大写 "SUGGESTIONS" 11px。
- 建议：改 Title Case + 11px 字号 + 16px 边距，语义上按 Raycast 分区命名（查询态用「结果 / 文件」）。

### V6 [P1] 窗口尺寸与位置
- 建议：宽 720→750；高度保持 520 或随内容 475~520 弹性（Raycast 固定 475，列表内部滚动）；垂直位置 workArea×0.18→×0.15。

### V7 [P1] 剪贴板页左右比例
- 基准：列表 285 : 详情 465（≈0.38 : 0.62），详情内图片预览上置、下方「Information」键值表（行高 28pt，标签左值右）。
- 现状：列表 374 : 详情 320（≈0.54 : 0.46）。
- 建议：`--launcher-detail-width` 320→465（或比例 62%），信息区键值表对齐 28px 行高。

### V8 [P2·需拍板] 强调色
- 基准：Raycast 默认主题强调色为品牌红（#FF6363 系），选中行是中性白覆盖。
- 现状：Leaf 用 systemBlue（`--launcher-accent: #0a84ff`）+ 左侧蓝色选中指示条。
- 决策点：a) 跟 Raycast 换红；b) 保留系统蓝但去掉左指示条改全覆盖式选中背景。任选其一需在 DECISIONS 落一条。

### V9 [P2] 计算器结果行
- 基准：独立大字版式——表达式 30pt + 结果 30pt（乘号渲染为 ×），下方 14pt 灰字小标签 Expression / Result，中间竖分隔线；底栏主操作变「Copy Answer ↵」。
- 现状：Leaf 无计算器模块（V4 已列为功能差距，此处补版式基准供实现时用）。

## 三、交互层（按优先级）

### I1 [P0] Esc 的导航语义
- 基准（实测）：Raycast 推入页（剪贴板历史）按 Esc **返回根列表**，窗口保持；根列表 Esc 才关窗。失焦关窗为另一条路径。
- 现状（实测）：剪贴板页按 Esc **整个胶囊窗直接隐藏**。
- 建议：渲染端路由栈上，Esc 优先 pop 一级路由；仅根态 Esc 才回传 hide。

### I2 [P1] 底栏主操作文案随选中项变化
- 基准（实测）：Raycast 底栏按钮文案 = 当前选中项的主动作，动宾结构：安装类「Install Update ↵」、计算器「Copy Answer ↵」、剪贴板「Paste to 通用控制 ↵」（**带目标应用名**）、查询态命令「Open Command ↵」。
- 现状：固定「↵ 执行」。
- 建议：底栏主按钮绑定选中项第一动作的动词短语 + 选中目标的（剪贴板页加「粘贴到 <前台应用名>」）。

### I3 [P1] 推入页搜索栏加返回按钮
- 基准：剪贴板页搜索栏左侧有 ← 返回按钮（23×22），点击回根；输入框 placeholder 变为「Type to filter entries…」（页面内过滤语义）。
- 现状：Leaf 无返回按钮（只有 Esc），placeholder 不变。
- 建议：随 I1 的路由栈补 ← 按钮；页面级 placeholder 切换。

### I4 [P1] Action Panel 结构对齐（⌘K）
- 基准（实测）：**独立窗口** 460×390，锚定主窗右侧；底部 40pt 动作过滤框；分区头 + 每行 12×14 图标 + 36pt 行距 + 右侧**逐键帽**快捷键（⌘/⇧/C 每个一个 18pt 键帽）；单页可显示 8+ 动作（含 Configure Command… 等元动作）。
- 现状（实测）：主窗内下拉浮层 694×80，搜索框正下方；无过滤框、无分区、无图标、无键帽；仅显示一个动作（「执行 ↵」）。
- 建议：改为右锚定浮层（约 460px 宽）、底部过滤框、动作行带图标 + 右侧键帽；动作集补齐（复制/粘贴/主操作/固定/配置）。

### I5 [P1] 剪贴板日期分区粒度
- 基准：Today / Yesterday / 更早日期段。
- 现状：今天 / 更早（无「昨天」）。
- 建议：补「昨天」段。

### I6 [P2] 类型筛选入口位置
- 基准：「All Types」下拉嵌在**搜索栏右侧**（126×32），筛选时搜索栏语义变为「过滤当前列表」。
- 现状：「按类型筛选」popup 在列表列头（57×23）。
- 建议：迁入搜索栏右侧，样式对齐。

### I7 [P2] 底栏面包屑
- 基准：底栏左端是当前页面包屑按钮（「Clipboard History」143×28），可点击（返回/定位）。
- 现状：无。
- 建议：随 I3/I4 一并加路由指示。

### I8 [P2] 剪贴板列表行信息密度
- 基准：单行「Image (379x211)」+ 徽标，38pt；无日期后缀（日期由分区头承载）。
- 现状：两行（内容 + 「类型 · 来源 · 相对时间」元数据行）51px。
- 决策点：保留两行（信息更足，但与 Raycast 观感不同）或对齐单行 + 元数据并入 hover/详情。**需拍板**。

### I9 [P2] 加载态
- 基准（官方文档）：`isLoading` 在窗口顶部显示进度指示，列表先出后填。
- 现状：未验证，可能缺失统一加载指示。
- 建议：检查各页 slow path（OCR、日程、文件搜索）是否有一致的顶部加载条。

## 五、设置窗基准（Leaf 设置页重构时使用）

Raycast Settings 实测结构（独立窗 800×786）：
- 左侧栏 227pt：顶部「Search settings」32pt 搜索框 → Account 卡（44pt）→ 导航项 32pt/行、22×22 图标（General / Launcher / Shortcuts / Keyboard / Cloud Sync / Advanced / About + 每个扩展一项）。

- 采集于 About / General 两面板，可作 Leaf 设置窗「侧栏 + 行式布局 + 右对齐控件」的版式规范。

## 六、刻意不对标（保持现状）

- **玻璃材质**：Leaf 用系统 vibrancy/acrylic 半透明（既有决策），Raycast 为不透明纯色面板——保留。
- **中文文案**：Raycast 英文；Leaf 面向中文用户——保留，仅对齐**信息结构**（分区命名、动宾按钮文案模式）。
- **⌘1-4 模块快捷键**：Leaf 自有设计（设计注释承诺永不重编号），不跟随 Raycast 数字徽标语义。
