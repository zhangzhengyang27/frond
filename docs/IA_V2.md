## 1. 顶层模型：门 + 家

Leaf 有两个常驻界面，各回答一个问题：

```
┌─────────────────────────────────────────────────────┐
│  Command Layer（命令注册表）—— 唯一真理源              │
│  src/shared/commands.ts + src/shared/search.ts       │
│  模块 + 系统页 + 动作 + 插件命令 + 本机应用             │
└──────┬──────────┬──────────┬──────────┬─────────────┘
       │          │          │          │
   胶囊启动台    ⌘K 面板    托盘/Dock    ⌘2-4
   (Alt+Space)  (窗口内)   (系统入口)   (键盘直达)
       │
       ▼
┌─────────────────────────────────────────────────────┐
│  Workspace（主窗口）：左侧导航 + 右侧内容              │
│  承载持久工作区（片段/录屏/番茄钟）+ 管理页（插件/设置）  │
└─────────────────────────────────────────────────────┘
```

### 分工契约

| 关注点 | 启动台（门） | 主窗口（家） |
| --- | --- | --- |
| 定位 | 进入与执行 | 浏览与管理 |
| 搜索 | 全量命令（注册表 + 插件 + 应用） | ⌘K 读同一份注册表 |
| 插件 | **运行**（胶囊内 / 分离窗） | **管理**（装 / 停 / 卸 / 同步，`/launcher`） |
| 模块页 | 打开沉浸式独立窗口（无壳，搜什么只看什么） | 承载（带侧边栏的工作台） |
| 状态 | 无状态，关掉即走 | 持久（历史 / 收藏 / 草稿） |
| 交互 | 键盘优先 | 鼠标友好 |

## 2. 统一命令注册表

**一切入口喝同一口水。** 四个入口（胶囊 / ⌘K / 托盘 / Dock）+ ⌘2-4 全部从同一份注册表取命令。

| 件 | 位置 | 职责 |
| --- | --- | --- |
| 注册表 | `src/shared/commands.ts` | `CommandEntry` 类型；静态命令（模块 + PENDING + 系统页 + 动作） |
| 搜索引擎 | `src/shared/search.ts` | 归一化 / 打分 / 高亮，胶囊与 ⌘K 共用，排序完全一致 |
| 执行器 | `src/renderer/src/utils/commandRunner.ts` | 同一命令从任何入口触发的执行语义一致 |
| 模块真理源 | `src/shared/modules.ts` | `MODULES`（含 `category` 侧边栏分组）+ `PENDING_MODULES` |
| 动态命令 | 消费方运行时追加 | 插件命令（`launcher.listPlugins`）、本机应用（`getApplications`） |

命令类型：`module`（家中页面）/ `page`(系统管理页) / `plugin` / `app`。

## 3. 主窗口导航（侧边栏三分组）

```
工具      屏幕录制 ⌘2 · 番茄钟 ⌘3 · 代码片段（PENDING）（⌘1 随截图下线空出，2026-09-17）
启动器    启动器 ⌘4（插件管理，原 /fastSearch）
系统      设置 · 数据迁移 · 关于（shared/commands.ts SYSTEM_PAGES）
```

- 模块归 `MODULES.category`（`tool` / `launcher`）；系统页归 `SYSTEM_PAGES`。
- Hub（`/`）保留 Hero + 分组卡片 + 最近使用 + 收藏，作为「家」的内容页。
- 导航可见性只由 `MODULES` / `SYSTEM_PAGES` 决定；overlay / floating / onboarding 路由天然不进导航。

## 4. 窗口语义与快捷键

- 路由 `meta.window`：`shell`（默认）/ `overlay` / `floating` / `capsule`，详见 `docs/ROUTING.md`。
- 快捷键三层契约：Alt+Space（门·全局）/ ⌘K（门·窗口内）/ ⌘2-4（家·直达；⌘1 随截图下线空出），详见 `docs/SHORTCUTS.md`。

## 5. 命名规范

- 「启动器」= launcher（胶囊窗 + 插件体系 + `/launcher` 管理页）。
- **禁用**「快速搜索 / fastSearch」作为产品词；旧路径 `/fastSearch` 保留 redirect。

## 7. 北极星：Raycast 体验

产品方向（2026-09 确认）：**以 Raycast 为体验标杆——启动台是产品的主形态**。
完整差距分析见 `RAYCAST_GAP_ANALYSIS.md`（8 维度），执行状态见 `RAYCAST_PARITY_PLAN.md`。

已对齐的部分：全局热键胶囊、失焦即隐、光标屏定位、统一命令注册表与搜索引擎、
插件命令 + 副输入框 + 分离窗口（≈ Raycast 的 Open in Window）。

核心差距与演进路径（增量演进，不推倒重来）：

1. **命令在胶囊内呈现结果**：Raycast 的命令在启动台窗口内直接渲染列表 / 详情 / 表单，
   而不是把用户踢去另一个大窗口。Leaf 的插件 BrowserView 机制已经是这个模型——
   把内置模块的快捷交互（开始专注、片段搜索）做成「第一方插件页」挂进胶囊。
2. **列表-详情 UI 基元**：为第一方 / 第三方插件提供极简 List / Detail 组件与键盘导航约定
   （对应 Raycast 的 Actions 栏），保证胶囊内交互的质感一致性。
3. **主窗口降级为管理面**：重型模块（片段编辑器、录屏剪辑）走分离窗 / 独立窗；
   主窗口收敛为设置 + 管理中心；入口优先级变为 胶囊 > 托盘 > 主窗口。
